# Build a package in your browser or terminal

The static GitHub Pages site accepts your owned `RGFX.EXE`, detects Windows or Linux with a manual override, and downloads a ZIP. A worker does the work entirely on your device. The page fetches static runtime kits; it never uploads your executable, generated assembly or package.

Both interfaces use the same Rust library for executable recognition, normalization of the two supported builds, guarded patching, assembly postprocessing, executable reconstruction and ZIP packaging. Pinned SR and NASM run as WebAssembly tools. The browser supplies an in-memory WASI filesystem; the local CLI runs the same tools through Wasmtime.

The result is an experimental runtime snapshot, with the existing project's acceptance limits. Linux menu and original-function checks and Windows Wine checks do not establish full-game completion, hardware playback or real-Windows acceptance. The initial kits predate controller support on main.

## Use the local CLI

Install Rust and [Wasmtime](https://wasmtime.dev/), then build:

```sh
cargo build --locked --release -p maiko-patcher --bin maiko-patcher
```

Download the target's runtime kit from the release linked in `web/kits.json`, and run:

```sh
maiko-patcher build --input /path/to/RGFX.EXE --target linux \
  --kit linux.zip --output maiko-linux-x64.zip
```

Use `--target windows` with `windows.zip` for Windows x64. `--wasmtime PATH` selects a local Wasmtime installation. The CLI uses a private temporary directory, reads the original game without modifying it, and refuses to overwrite the output ZIP.

Extract the generated ZIP into a separate writable folder. Windows users open `RUN.cmd` and choose the original game folder. Linux users run `sh RUN.sh /path/to/Redguard`; the package includes SDL2, SDL2_mixer, GLU and OpenGL dispatch libraries. It needs a glibc 2.36 or newer desktop with X11/XWayland and a working OpenGL driver. Saves and settings go to the package's `user-data` directory.

## Export runtime kits

A kit contains a native runtime template with **every translated game section erased**, hashes of the locally assembled sections, resolved relocation address fields, WASI tools, upstream support includes, launchers, runtime dependencies and licence/source files. It contains no original executable, translated assembly, translated engine object or complete native game executable. Unwind metadata is generated by the upstream support macros and retained in the host template.

The exporter compares every non-relocation byte of each game section with the accepted native executable. It rejects differences and nonzero padding, erases the complete game section ranges, then reconstructs and compares the complete executable byte for byte before exporting. Consumers check section hashes, require empty template slots, apply the address fields, and require the accepted final executable SHA-256 before producing a package. A metadata or assembler change requires newly accepted kits; it cannot silently produce a different executable.

Maintainers need Rust, Git, Make, curl, tar and the pinned upstream repositories in `.cache/sr` and `.cache/openglide-ng`. Build the WASI tools without any game input:

```sh
cargo run --locked -p maiko-patcher --bin maiko-kit -- tools
```

This downloads hash-pinned WASI SDK 29 and NASM 2.16.01 and builds SR at the repository's pinned revision with its documented patches. NASM's version matters: newer versions can choose equivalent instruction encodings that fail the exact-build check.

Assemble the engine from a recognized owned image with these tools. Independently build and accept the native runtime using [building.md](building.md). Create a **curated** flat runtime directory containing only the platform's DLLs/shared renderer and runtime libraries, launcher, `README.txt`, `LICENSES.txt`, and corresponding upstream source archives/build scripts. Include all applicable notices. The Linux package bundles SDL2 2.30.11 and SDL2_mixer 2.8.1, with their unchanged source archives and build configuration. The mixer keeps WAVE playback and disables optional compressed music codecs. It also includes Debian bookworm GL/GLU dispatch libraries and their notices. Never pass the artifact directory as that directory: it contains game-derived files.

```sh
cargo run --locked -p maiko-patcher --bin maiko-kit -- export \
  linux /path/to/accepted/redguard-native /path/to/rgfx.o \
  /path/to/curated-runtime ACCEPTED_BUILD_ID linux.zip
```

For Windows use `windows`, the accepted `.exe`, and the matching NASM `.obj`. Review the exported inventory and confirm all `csegNN`/`dsegNN` file ranges in `template.bin` are zero before publishing. Keep game-derived intermediates private.

## Build and deploy the site

Use Bun, Rust's `wasm32-unknown-unknown` target and `wasm-bindgen-cli` 0.2.129:

```sh
bun install --frozen-lockfile
bun test web
bun run build
```

`web/kits.json` pins immutable Maiko release URLs and SHA-256 hashes. The site build checks the downloads and serves them from the same origin. For a local build, `MAIKO_KIT_DIRECTORY` can point to a directory with the same checked `linux.zip` and `windows.zip`. The content security policy restricts browser requests to the page's origin.

`.github/workflows/pages.yml` runs the source checks, builds Rust/WASM and the static page, uploads the Pages artifact, and deploys on main or manual dispatch. Set **Settings → Pages → Source → GitHub Actions** before deploying. The managed GitHub App needs Pages write permission to enable that setting through the API.
