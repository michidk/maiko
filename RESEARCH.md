## Observed adaptation work

1. The LE loader accepts RGFX without a loader patch.
2. Five Watcom string routines have two instruction entry points overlapping a `test ax, immediate`. Metadata expands each into the same test plus a jump, leaving the alternate `mov edi, ecx` entry intact. Resume labels must also be explicit roots. This preserves defined flags and registers; no game binary is edited.
3. 130 decorated Glide loader names reside in the executable code object. SR's relocation heuristics tried to decode them as instructions. The exact-build profile marks these string addresses as data. This number is not a count of APIs needed by the menu.
4. SR's x64 instruction switch needed additional x87, MMX, bit-scan, CPUID, JECXZ and string-scan handling. These are experimental compiler changes, not a proven complete translation. In particular, emitting host CPUID is x64-specific.
5. Native startup must be explicitly seeded. An earlier successful assembly emission did not cover the original startup; adding the entry alias exposed SIDT. A zero translator exit code alone is insufficient evidence.
6. The diagnostic traps cover four far transfers, five LSL instructions, one LAR, one HLT and one SIDT. The associated descriptor, interrupt and mixed-mode semantics need a runtime design or native library replacement.
7. Translation expands branch distances. Removing forced short encodings lets NASM select suitable encodings for ordinary jumps. Short-only instructions remain checked by the assembler.
8. Individual byte directives made assembly expensive. Two initial attempts were stopped, one manually and one at 120 seconds, with memory growing into several GiB. Compacting repeated bytes and packing adjacent byte declarations made the final Windows build and Wine check complete in about 19 seconds in the measured run. This is a single local build measurement, not a gameplay performance claim.

## Runtime design finding

SR's supported games start at game-specific native entry points and replace libraries. Trying to carry the DOS extender startup through unchanged brings PSP/environment segments, interrupt descriptors and low-memory assumptions into the host.

A short X-32 startup-branch experiment attempted to supply a PSP/environment below 1 MiB. Its fixed allocation failed under Wine before execution; the implementation was discarded. We have not established that low-memory allocation is generally impossible. Do not treat guessed DOS-version replies or blanket successful interrupt stubs as progress toward a functioning menu.

The native target now adapts the original C runtime/game entry boundary and a subset of file/heap/time services. Glide integration and original-game interaction remain open. Keeping the full DOS startup would require a more extensive DOS/extender compatibility runtime. The original-entry diagnostic remains separate.

## Native entry boundary inspection

`REDGUARD.EXE` in this install is a PE32 Windows GUI executable (launcher), whereas `RGFX.EXE` is the LE engine image. It is not evidence of an available software-renderer DOS build.

The generated translation shows the CRT wrapper at original address `0x113B1A` loading arguments from `0x34131C` and `0x341320` into EAX and EDX, then calling `0x20000`. This is consistent with a Watcom register-convention main entry. It does not establish that calling it directly is safe. Before that edge, startup clears BSS and runs the initialization dispatcher at `0x113B6A`.

The candidate main immediately calls `0x98673` with EAX=4. That function takes the bit-4 branch into `0x984AD`, which clears 4,000 bytes starting at physical address `0xB0000`. Thus the first game initialization still assumes DOS text-video memory even when extender startup is bypassed. Later, the argument parser at `0xC7F20` dereferences the argv pointer and calls allocator-backed routines. A zero-register main probe would be invalid.

A viable native entry adapter needs a 32-bit-addressable argument vector, appropriate CRT globals and initializers, stack checking, native heap/file/time interfaces, and a replacement for the debug text display. Glide and input remain further requirements. These are concrete adaptation tasks, not facilities SR supplies automatically. No main-entry bypass was shipped in the diagnostic ZIP.
